## Session — 2026-07-13 — READINESS LAZY-EXPIRY — MERGED to `main`

Branch `claude/work-session-5efb6c`. Commit `6b9d15d`. **App-layer, NO
migration** (the `expired_at` column + the one-live-claim unique index already
existed — only the *writer* of the stamp changed). tsc + eslint clean; vitest
169 → **176**. On `main`, **not prod**.

**The last designed readiness slice.** A readiness credit's 21-day window has a
frozen deadline (`expires_at`, stamped at activation) but nothing wrote the lapse
*event* (`expired_at`). The retired plan was a nightly cron; the settled design
(2026-07-11) is to stamp **lazily, on the next touch** of the row — a packs-page
read, and (correctness-critical) at re-claim time — mirroring the `/session`
runner's existing lazy-expiry.

**Why it's correctness-critical, not cosmetic.** The
`idx_nclex_readiness_credits_one_live_claim_per_pack` unique index counts a claim
as live unless `expired_at` (or `revoked_at`) is set. So a lapsed-but-unstamped
credit still occupies the `(user, pack)` slot, and re-claiming that pack with a
fresh credit `23505`'d — wrongly refused as "you already hold this pack" — until
the old row is stamped. The claim actions now stamp first, freeing the slot.

**Built (all app-layer):**
- `lib/payments/readiness-credits.ts` — new pure `isLapsedLive(credit, nowMs)`
  (activated · not terminal · `expires_at` in the past); corrected the stale
  "nightly sweep" comments to lazy-stamp-on-touch. +7 unit tests.
- `lib/payments/readiness-expiry.ts` **(new)** —
  `sweepLapsedReadinessCredits(userId, packId?)`, a service-role write (credits
  have no student-write RLS). Idempotent + race-safe by its WHERE clause
  (re-checks activated / not-terminal / deadline-past, satisfying the
  expiry-requires-activation + one-ending CHECKs); best-effort (returns 0 on
  error, caller carries on).
- `lib/payments/readiness-packs-view.ts` — sweeps before the read (self-heals
  the row) **and** uses `isLapsedLive` in the stage derivation so the card flips
  to lapsed/claimable even in the rare render where the best-effort write didn't
  land. One clock read (`now`) reused throughout.
- `lib/payments/readiness-claim.ts` — folds the stamp into both actions:
  `claimReadinessPack` scoped to the target pack (after pack validation, before
  finding the fresh credit), `claimAllReadiness` before its read.

**Scope call (with Sam, pre-build):** the abandoned-sitting finalisation (a
sitting whose 3h20m clock ran out while the student was away) is **left to the
existing `/session` lazy-expiry**, not folded into the packs page — the packs
page has no need to finalise attempts, and the SITTING→USED flip already
self-heals on the next session load. `getMyCredits` stays a pure reader (one
write path per surface).

**Verification.** tsc + eslint clean; full vitest 176 pass. No student was
logged into the dev browser and I can't enter a password, so I proved the
mechanism at the DB level against a real backdated ACTIVE credit: (A) the exact
sweep predicate stamps **only** the lapsed row — USED / unactivated credits
untouched, no CHECK violation; (B) idempotent (0 rows on a second run); (C)
re-claim **succeeds** once the stamp lands; (D) the same claim onto a still-live
pack **collides (23505)** — the exact bug the stamp prevents. Then **Sam's
browser test** exercised the real code path: logging in as the tutor account and

**What shipped (to the session branch).** `MATRIX_MR` — Matrix Multiple
Response, a new **self-contained** NGN item type. A rows × columns grid where
each row has **one or more** correct columns (checkbox per cell), scored
SATA-style per row. Mirror of the existing `MATRIX` (radio, exactly one per
row) — legacy `MATRIX` left 100% untouched. First end-to-end use of the
"Adding a new question type — wiring checklist" captured last session.

**Design — the 4 open questions settled one-at-a-time with Sam** (BUILD_LIST +
`questions-and-wrappers-rebuild.md` carry the full write-up):

- **Q1 — can a row have zero correct?** No — **require ≥1 correct per row.**
  This was the hard one; grounded it in a **web check of the NCSBN spec**
  (paywalled pages 403'd, but several independent sources converge): Matrix MR
  = 4–10 rows, 2–3 cols, per-column +/- scoring floored at 0, and crucially the
  real exam **forces the student to tick ≥1 box per row to proceed** — which
  makes an all-false row literally unanswerable. So real items always have ≥1
  correct per row. Surfaced as a clear editor block, not a silent fail.
- **Q2 — scoring:** **SATA-style per row.** New `scorePerRowMulti` in
  `lib/scoring/functions.ts` runs the existing `scorePlusMinus` per row (+1
  correct / −1 wrong, floored at 0 within the row), summed across rows. Max
  marks = total correct cells across all rows (a row with 2/1/3 correct → 6
  marks). `is_correct` (full credit) only when every row is exactly right.
- **Q3 — submit gate:** **hard gate** — the student must pick ≥1 per row; the
  runner's submit hint **names the still-empty rows** ("row 2, 4 still empty").
- **Q4 — bounds:** mirror MATRIX exactly (hard **2–10 rows / 2–6 cols**) + an
  advise > block amber advisory toward the NGN norm (4–10 rows, 2–3 cols).
