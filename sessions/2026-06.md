## Session — 2026-06-15 (build) — Live sessions: marker/planner split (Slices 1 + 2)

> Branch `claude/modest-nash-03f683`. **Built Slices 1 + 2 of the live-session
> marker/planner split** (designed + finalised the same day) plus two fix-ups.
> Sam-tested on dev; tsc + eslint clean; **MERGED to `main`**, not yet released
> to prod. One migration `20260703120000`.

**The problem.** A live session was modelled as an ordinary activity whose
date / join-link / recording lived on the **programme-template** payload — so
every cohort shared one stale time/link. A live session is an **event**, not
content; those fields are per-run.

**Slice 1a — events out of progress (no migration).** Removed
`ONLINE_LIVE_SESSION` from the manual-mark types; excluded it from the
completion denominator **and** the "Up next" pointer (so it can't freeze the
pointer on a thing that's never completable); `isDone` forced false; a neutral
📅 **Event** chip replaces the task pills; matched on the tutor side (excluded
from cohort-analytics completion). Governing rule, agreed with Sam: *only
verified completion counts* — a live session doesn't count in v1 because there's
no verifiable signal yet.

**Slice 1b — marker/planner split (migration `20260703120000`).** New
`nclex_cohort_live_sessions` `(cohort, marker) → schedule` table + RLS (tutor
ownership · enrolled-student read · SUPER_ADMIN); gut the template payload to a
`{ typical_duration_minutes }` **marker**; **dropped self-paced live sessions**
(tutor-led only — *blurred*, not hidden, in the activity picker). The cohort
**Sessions** tab became the **planner** (markers + scheduled/unscheduled state)
with a **reworked schedule editor** (platform · join URL · meeting ID · passcode
· joining instructions · date/time · duration · recording). Re-pointed the
student viewer + tutor Home "This week" to read the planner ("Date to be
announced" when unscheduled); `HomeSession` gained `cohortId` / `cohortName`.

**Slice 2 — integrity cue + one-offs (no migration).** "Needs scheduling →"
cue on the cohort checklist for an included + published but unscheduled marker
(links to the Sessions tab via `usePathname`, no `programmeId` threading).
**"+ Add session"** one-off (Option B) — atomic
`createCohortOnlyLiveSessionAction` writes a cohort-only marker + its schedule in
one validated step + "Remove" for cohort-only sessions; the planner exposes the
programme's weeks for the picker.

**Design discussions settled with Sam.** (1) Completion = *only verified
completion counts* — not a reversal, just no verifier yet. (2) **Attendance →
derived completion** is the confirmed **next** slice (tutor-marked presence →
a derived `ATTENDANCE` row; an *absence* becomes a real "missed it" signal). (3)
Moving live sessions **out of the curriculum entirely — rejected** (the live
call anchors the week: pre-read → call → post-quiz). (4) **Two-way creation
(Option B):** a cohort-only live session is just a cohort-only **marker**, so —
after Sam pushed back — it's also added from the **cohort-only curriculum
picker** (add now, schedule later via the cue), in both the loose **and**
in-block pickers.

**Two fix-ups (both found by Sam testing).**
- **Add-session lost input on a bad URL.** A scheme-less URL ("zoom.com") failed
  validation; the old two-step create-then-schedule left an orphan unscheduled
  marker and discarded the tutor's input. Fix: **forgiving URLs** (auto-`https://`;
  still reject genuine garbage — the join URL is a clickable student link) via a
  shared `lib/cohorts/live-session-schedule.ts`, and an **atomic, validated-first**
  create so a bad field shows an inline error with the form intact and *nothing*
  written.
- **`'use server'` `ReferenceError`.** A `export type {…}` re-export + mixed
  value/type import inside a `'use server'` module emitted a runtime reference to
  a type with no binding → `ReferenceError` at module load, killing every action
  (add / schedule / delete) and the Sessions tab. Fix: pure `import type` + drop
  the re-export; keep shared types/validators in a plain module. tsc/eslint miss
  it — dev-log only. Saved as the `reference_use_server_no_type_reexport` memory.

**Commits:** `6fcb98c` (doc finalise) · `a3bde5f` (1a) · `1bedd3f` (1b) ·
`40200c6` (2) · `91defbe` (URL fix) · `be7e5ca` (cohort-only picker) · `6c8a9a8`
(`'use server'` fix) · docs/merge commit.

in ONE cohort, on the cohort Curriculum tab, without polluting the shared
programme template. Built **Option A** — a cohort-only item is an ordinary
`nclex_programme_activities` / `_blocks` row tagged with a nullable
`cohort_id` (NULL = template, set = cohort-only); reuses every existing
editor + render path.

### Debugging headline — modal-in-card traps (3 layers, same root)
The Edit + Add-first-cohort modals render as **DOM descendants of a
programme card**, which caused three escalating bugs:
1. **Twitch on open / "sits on the card."** The CD card's hover
   `transform: translateY(-2px)` made the card the *containing block* for
   the modal's `position: fixed` overlay → it anchored to the card and
   jittered as the hover transform moved. **Fix:** dropped the hover
   transform (shadow + border lift only).
2. **Translucent modal / page bleeding through.** The card's stacking
   context meant sibling cards (later in the DOM) painted over the trapped
   overlay.
3. **Click-through to a programme page.** Same trap — the overlay didn't
   cover the cards' overlay links, so clicks fell through.
   **Fix for 2 + 3:** **portal both modals to `document.body`** (escape the
   card entirely). The original card never hit this because its hover was
   box-shadow-only and… it predated the richer in-card affordances.

Sam opened by checking we both remembered last session's decisions. Walked

**(1) a shelf is ATOMIC** — ONE activity + ONE attachment (`shelf_id` set,
`note_id` NULL), never one-activity-per-note; **(2) completion is
DERIVED** — a rollup of member-note `marked_done_at`, no progress row.

`shelf_id` + `skipped_note_ids` + the `note_id` XOR `shelf_id` CHECK since

adding `'SHELF'` to the activity-type CHECK.**

Then settled, in plain terms with Sam, four design points:
- **`skipped_note_ids`** = "Hide in this unit" — a per-placement, reversible
  local trim that never touches shelf membership.
- **Tutor card stays uniform** (like every other activity); all shelf detail
  + the member-notes-with-hide controls live in the **edit modal** — matches
  how every activity behaves (Sam's call, diverging from the CD prototype's
  special card).
- **Mixed visibility — "Option A" (full).** A shelf can hold notes whose own
  visibility excludes the target programme. Warn at attach ("N of M won't be
  visible here"); in the modal show a DISTINCT state "Not visible to this
  programme · Make visible here" (never conflated with "Hidden here ·
  Unhide"). "Make visible here" = the same op as editing the note to add the
  programme (inserts a `_note_visibility` row; only ever widens). Sam's
  framing: mixed-visibility is rare/self-inflicted (a reusable shelf carrying
  programme-scoped notes contradicts the shelf's purpose), so we don't
  over-invest — warn + read-the-state + one-click fix is plenty.
- **Live membership** — the shelf reads members at render time, so adding a
  note in the library updates every attachment. New notes opt-out (show
  unless skipped); the skip-list keeps trimming as the shelf grows. The
  11.12c hint explains a change to students.
