MyNclex — Curriculum Authoring UX
Working mockups · originally 2026-04-20 · revised 2026-05-10 (programme/cohort split) · revised 2026-05-11 (curriculum architecture rework)
Companion to mynclex/docs/product-plan/curriculum-authoring-ux.md · Reference only, not final design
2026-05-11 — Curriculum architecture rework. Modules renamed to blocks (workflow groupings of related activities, often tutorial-anchored — not academic chapters). Weeks abstracted to a generic units layer; same DB layer. Unit label (Week / Module) is a separate tutor choice on the programme, decoupled from delivery mode — smart default is Week for tutor-led and Module for self-paced, but the tutor can override either way. Activities can live loose under a unit or inside a block; blocks are not mandatory containers. Delivery modes introduced — every programme is tutor-led (with cohorts) or self-paced (no cohorts); both ship in v1. Screens below show tutor-led + Week-labelled mode; self-paced reuses screens 1–7 (with the cohort screens 8–11 hidden) and an additional self-paced enrolment + dashboard set queued for design.
2026-05-10 — Programme/Cohort split. Programme is now the reusable design (curriculum + identity + pricing). A cohort is one specific run of that programme (dates, seats, enrolment, schedule). Curriculum lives at the programme layer; cohorts hold a checklist of which template activities are in. Content edits to the programme propagate to every live cohort; structural changes don't — the tutor opts in per cohort. See screens 1–7 for the programme layer (curriculum design) and screens 8–11 for the cohort layer (specific runs).

Screen 3 · Programme layer
Units Overview — Unit view (default; labelled per the programme's unit_label)
The Curriculum tab inside a programme. A grid of unit cards. Empty units are shown dashed so the tutor always sees N cards for an N-unit programme. Segmented toggle at top-right switches to the Calendar view (Calendar option hidden in self-paced — no cohort calendar to project against). This is the programme layer — curriculum edits here propagate to every live cohort (tutor-led) or to every enrolled student (self-paced). UI labels per the programme's unit_label: Weeks / W1, W2, … (shown here) or Modules / M1, M2, …. Independent of delivery mode.

Screen 4 · Programme layer
Units Overview — Calendar view (tutor-led only)
Same curriculum, different projection. Rows are units, columns are days. Calendar shows scheduled activity types (not blocks), so a block can span days naturally. Text, PDF, and External link activities are "anytime" work and don't appear here. Each chip carries its block reference (e.g. "B2") when the activity belongs to a block — loose activities show without one. Day numbers shown here are curriculum-relative (unit 1 day 1, unit 1 day 2, …) — actual calendar dates are a per-cohort property, set on each cohort's start_date. Self-paced mode hides this view entirely (no cohorts → no release timeline). Note: the row-label "W1/W2/…" reflects the demo programme's unit_label = Week; a programme with unit_label = Module would show "M1/M2/…" the same way.

Screen 5 · Programme layer
Unit Builder — loose activities + blocks
Inside one unit of the programme curriculum (labelled per the programme's unit_label — Week N here, Module N if the tutor picked Module). The unit body is an interleaved stack of block cards (groupings of related activities the student treats as one push) and loose activity rows (sit directly under the unit, no block parent). Up/down arrows on every row for reordering (drag-and-drop deferred to v2). Two entry points at the bottom: "+ Add activity" (loose) and "+ Add block" (group). Edits here propagate to every live cohort (tutor-led) or every enrolled student (self-paced).

Screen 6 · Programme layer
Add-activity inline picker (loose or inside a block)
Same picker, two entry points: "+ Add activity to block" inside a block card, OR "+ Add activity" at the unit level (loose). The button is replaced in place with this 3×2 picker. After selection, the picker closes and the editor panel slides in from the right. On Save, the activity attaches to the invoking block (block_id = <block>) or as loose under the unit (block_id = null) depending on the entry point. Screen 11 · Cohort layer
Cohort curriculum — checklist view
Inside a cohort. Same shape as the Unit Builder (screen 5) — interleaved blocks + loose activities — but each row is a checklist entry pointing at a template activity (or a cohort-only entry) with cohort-specific release dates. Source pill on each row says Template (content read from the programme) or Cohort-only (content lives here, doesn't propagate). Block cards inherit the same source signal. Three add buttons per unit: + Add from template (template entries not yet in this cohort), + Add cohort-only activity, + Add cohort-only block.

How this differs from screen 5. The Unit Builder at the programme layer designs the shared curriculum. This view is the cohort's checklist — it determines which template entries are in this cohort only, plus any cohort-only adds (activities or whole blocks). Removing here doesn't touch the template; removing in the template doesn't auto-remove from active cohorts (only from new ones launched after).

About this file. These are planning-stage mockups, not final UI designs. Captures structural decisions from the 2026-04-20 curriculum authoring session, revised 2026-05-10 (programme/cohort split) and 2026-05-11 (curriculum architecture rework — modules → blocks, weeks → units, loose-vs-blocked activities, delivery modes — both tutor-led and self-paced ship in v1, unit label decoupled from delivery mode as a separate tutor choice).

Real UI will be built against the QAcademy brand and can refine layout, spacing, and typography. The structural decisions (hierarchy, layers, propagation rules, fields per activity type, reordering model, loose-vs-blocked rule, delivery mode dimension, unit-label decoupling) are what matter here.

See mynclex/docs/product-plan/curriculum-authoring-ux.md for the full written plan and mynclex/docs/product-plan/main.md for the canonical programme/cohort architecture, delivery-mode definitions, and unit_label rules.
