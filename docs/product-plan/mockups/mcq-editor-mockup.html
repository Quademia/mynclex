What you're looking at

The whole dashed-purple box is McqEditor — one of 9 self-contained editor components. It owns its own modal-topbar layout, its own tab structure, its own two-view shape, and its own Content body. The dashed-teal boxes inside the Classification and Housekeeping tabs are shared primitives — the bits that are genuinely identical across all 9 editors, so they're imported, not reinvented.

Architecture legend

Self-contained editor — one of 11 (9 question types + CaseStudyEditor + TrendEditor). Owns its own shell, tabs, preview, save/publish buttons.
Shared primitive — composed by editors that need it (e.g. ClassificationFields, HousekeepingFields, modal chrome, dirty-warning).

The other 8 question editors (TfEditor, SataEditor, SelectNEditor, MatrixEditor, HighlightEditor, ClozeEditor, DragDropEditor, BowtieEditor) follow the same template: own everything from the modal topbar inward, swap the Content body for whatever the type needs.

Columns deliberately not surfaced

  • question_type — implied by the editor identity itself (this is McqEditor); shown only as the locked MCQ pill.
  • parent_case_id — not editable from the standalone editor. It's set by the case-study editor when a question is attached to a case, and unset on detach.
  • content / correct JSONB — surfaced via their structured fields (Options + Correct + Per-option feedback), not as raw JSON.

Columns that don't exist (called out so we don't add them by accident)

  • Author — there is no author_id or created_by column on nclex_bank_items. If we want this in future, it's a schema addition, not a mockup omission.
  • Internal notes — no such column. Was speculation in the previous mockup draft.
  • CJMM step — lives on nclex_case_study_items (the case-study join row), not on the question itself. It only shows up in the wrapper editor.

Caveats — what this mockup is not

  • Save and Publish are intentionally disabled. Slice 1 builds the controlled-component shape and the read-side path; Save lands in Slice 2 and Publish in Slice 7.
  • Visual styling is illustrative. Real implementation will use the existing MyNclex design tokens; exact spacing, fonts, and weights will match the rest of the admin surface.
  • Classification dropdown lists are abridged here — the real primitive uses the full curated lists from lib/bank/classifications.ts (4 categories with cascading subcategories, 8 nursing subjects, 14 body systems, 6 Bloom levels).
  • Subcategory cascade is shown statically. The real primitive disables the Subcategory until a category is chosen, and swaps its option list to match.
  • No dirty-warning, no validation states, no keyboard shortcuts — those layer in later slices.
