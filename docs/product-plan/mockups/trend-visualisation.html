NGN Trend Items — Visual Primer

Four mockups showing what a Trend item looks like on screen, each paired with a different response question type.

Reference mockup · promoted to v1 on 2026-04-22 · shape: single question + time-series data panel

What a Trend item is

A Trend item is one question with a time-series data panel shown beside the stem. The "trend" is the data across timepoints — vitals over 3 hours, labs over 3 days, intake/output across shifts. The student reads the pattern and answers using one of the question types we already build (Matrix, Cloze, Highlight, or SATA).

Trend (this mockup)

One question item with a data panel alongside.

  • 1 question item
  • 1 question type (any of the existing ones)
  • Shared context = a small time-series table
  • No progression — one snapshot, one answer

Case Study (Slice 1.11 — separate build)

Six question items with a full patient chart alongside.

  • 6 question items
  • Up to 6 question types (one per item, can all differ)
  • Shared context = multi-tab chart that unfolds as you advance
  • Progression — chart reveals more rows on each question

Example 1 — Vitals trending + Matrix response

Classic clinical judgment scenario: vitals at three timepoints. Is the patient stabilising, deteriorating, or improving? The response is a Matrix — for each finding, pick the interpretation.

The trend table makes the direction of change visible at a glance. Without it, you'd have to embed all three timepoints into the stem text — which is what a curator would do today without a Trend widget.

Notice how the trend panel uses the exact same layout as Example 1 — just different data. That consistency is what makes Trend worth building as a reusable widget.

The highlight passage references the trend table — the student has to cross-read between panel and question.

Why this was originally deferred (and why we're building it now)

Reading between the mockups

Every Trend example above could be authored today as a regular Matrix / Cloze / Highlight / SATA — by putting the trend table into the stem text, or putting the data into the instruction field, or both. The clinical content lands. What's missing is the dedicated widget that renders the time-series panel cleanly.

That's why Trend was originally deferred: the schema already supports it (JSONB content is polymorphic), and the question-type architecture already supports adding one more branch. Building it is a matter of adding a content.trend_data field any host type can render above its stem, plus a trend-aware editor UI.

Update 2026-04-22: promoted to v1. Case Study (Slice 1.11) will land first — it's architecturally harder and establishes the wrapper pattern. Trend (Slice 1.12) follows, reusing Case Study's nullable-FK attachment mechanism.

If/when we build it — the shape

One sketch, not a commitment. The point is to show the shape is small:

// content column of a bank item that's also a Trend: { "host_type": "MATRIX", // the actual response type "trend_data": { // optional — presence triggers trend rendering "title": "Vital signs", "scenario": "Post-op day 1...", "timepoints": ["0800", "0900", "1000"], "rows": [ { "metric": "BP", "values": ["118/72", "104/64", "88/52"], "flags": [null, null, "abnormal"] }, // ... ] }, // ...plus whatever MATRIX normally puts here (rows, columns, row_label) }

Notice: no new table, no new question type, no migration. The field is optional and lives inside existing JSONB. Adding it later costs one editor enhancement and one renderer enhancement — nothing in v1 has to change.
