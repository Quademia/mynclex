MyNclex — App Shell Design

Planning doc + interactive mockup combined. Settled 2026-05-17 (planning; not yet built). Cross-cutting — applies to student, tutor, and admin shells equally.

1. Why this change

The current shell (shipped in the 2026-04-25 nav scaffold) puts a full-width topbar above a column-split layout. Both the sidebar and the page content scroll together — when the user scrolls down a long page, the sidebar slides off-screen with it, forcing them to scroll back to the top before they can switch sections.

Two problems we want to fix:

  1. Pinning — the sidebar should stay visible no matter how long the page is. Only the main content area scrolls.
  2. Density — the sidebar should be collapsible to an icon-only rail, so users who want maximum content width can reclaim the space.

A third change rides along with the pinning fix: the layout restructures so the sidebar runs floor-to-ceiling (full viewport height) and the topbar lives only above the content column. The MyNclex brand mark moves into the sidebar's own header, and the topbar becomes a per-context bar (breadcrumb + page actions + user menu) rather than a global header.

2. The interactive mockup

Click the toggle (three lines, top-left of the sidebar). Sidebar shrinks to icons only. Hover any icon to see its label as a tooltip. Scroll the content area — sidebar and topbar both stay pinned in either state.

4. Settled decisions

4.1 Sidebar is pinned

The sidebar stays anchored in place regardless of content height. Only the content column scrolls. Implementation: the sidebar column is its own scroll container; the content column is its own scroll container; the outer app shell is overflow: hidden.

4.2 Sidebar is collapsible

A toggle in the sidebar's own header collapses the sidebar to an icon-only rail (56px wide). In collapsed state, hovering an icon surfaces the item label as a tooltip.

4.3 Sidebar runs full height

The sidebar column extends from the top of the viewport to the bottom. The MyNclex brand sits in the sidebar's own header (top of the column). No full-width topbar above.

4.4 Topbar spans the content column only

Each audience-specific layout renders its own content-column topbar with whatever it needs there: breadcrumb / page title, product switcher (where applicable), user menu, role chip, page-level actions.

4.5 Collapse state is persisted

Once a user collapses the sidebar, it stays collapsed across page navigations and across browser sessions. Persisted in localStorage under a single key (e.g. mynclex.shell.sidebarCollapsed) so the preference applies globally across all audiences — same user, same choice on bank, tutor, admin surfaces. (Per-audience persistence considered and rejected for v1 — too granular for too little gain.)

4.6 Tooltip on collapsed hover

When collapsed, hovering an icon shows the item's label as a small dark tooltip to the right of the icon. Solves the "what does this icon do?" discoverability problem without forcing the user to expand.

5. Tutor "My Bank" — collapsed-mode behaviour

The tutor global sidebar's "My Bank" item has three child rows (All questions / Case Studies / Trend datasets). In the current expanded layout, these render as an inline expand below the parent. When the sidebar is collapsed to icon-only, the inline expand cannot fit.

Two options considered, one adopted:

Option Behaviour when collapsed Decision
A — Click goes to default Clicking the My Bank icon navigates to the parent's href (/tutor/bank/all). Children are inaccessible until the sidebar is expanded. Adopted v1. Simpler implementation; users who need a specific child can expand the sidebar (single click) to reach it.
B — Hover flyout Hovering the icon pops out a small floating sub-menu listing the children. Click a child to navigate without expanding the sidebar. Considered. Better UX in some senses, but adds positioning complexity and an extra interaction layer. Defer to v2 if real demand surfaces.

6. Mobile behaviour

Mobile (≤640px) already uses a stacked layout — sidebar above content as a horizontal bar — per the existing styles/nav.css. The collapse toggle does not apply on mobile; the sidebar's stacked form is already compact. No change needed.

Tablet sizing (641px–960px) gets the desktop layout. Default collapsed state on first load for tablets is a v2 polish item; v1 defaults to expanded everywhere on desktop+.

7. Default state on first visit

On a fresh load (no localStorage entry), the sidebar renders expanded. This matches the current behaviour and keeps the navigation discoverable for new users who haven't yet learned the icon set.

8. Implementation surface

Concretely, the shipping change touches:

  • components/shell/app-shell.tsx — restructures the outer layout so the sidebar column wraps both the brand-header and the nav-rows in a single floor-to-ceiling column; the topbar moves into the content column.
  • styles/nav.css + styles/shell.css — new grid template for the app shell; sidebar scroll container pattern; collapsed-state classes (.shell-collapsed); tooltip styles for collapsed nav items.
  • components/nav/shared/ — new sidebar-header.tsx (brand + toggle button) and a tiny useCollapsed hook backed by localStorage (or equivalent client-side store).
  • Audience layouts (app/(app)/student/*/layout.tsx, app/(app)/tutor/*/layout.tsx, app/(app)/admin/*/layout.tsx) — each updates to pass its sidebar config + content-column topbar slot into the new shell shape.
  • components/nav/student/product-switcher.tsx, role-chip, user-menu, etc. — these all currently live in the old full-width topbar; need to relocate into the new content-column topbar.
  • components/nav/admin/sidebar.tsx — its existing .sidebar-footer pattern still works (footer pins to bottom of the sidebar column), but needs to be revisited in collapsed mode.

9. Open questions (slot at build time)

  • Collapsed-state visual when there's no brand text. Do we render a small "M" logo at the top in collapsed mode, or just the toggle button? Most apps put a logo. Lean toward yes, but a single-letter mark needs designer review.
  • Admin sidebar footer in collapsed mode. The admin footer currently shows role + permission count. Collapsed mode either hides the footer entirely or shows just a tiny icon. TBD with first build.
  • Keyboard shortcut to toggle. Many apps bind Cmd/Ctrl+B. Not v1-critical but cheap to add.
  • Transition timing. 200ms ease for the grid-column-width transition feels right in the mockup. Worth a designer pass once it's in real product context.

10. Not in scope

  • Hover-flyout sub-menus for parent items with children (deferred to v2 — see §5).
  • Per-audience collapse persistence (rejected — global single setting in v1).
  • Multi-pane layouts beyond the sidebar + content split (e.g. right rail). Out of scope for this revision.
  • Animation polish (icon-to-label fade, label fade-in on expand, etc.) — base CSS transition is enough for v1; polish is a follow-up.
