Making the runner work on a phone

The runner is a three-region desktop shell — 56px topbar with nine controls, a fluid question column, a fixed 240px grid rail — plus a 924px-minimum split layout for case and trend questions. Below ~950px it stops working; below 420px several regions are unusable. Everything below is grounded in styles/runner.css, the four runner-*.tsx files and the eleven per-type runners.

Part 1 — What actually breaks

BLOCKERCase & trend split never fits
.rn-split { grid-template-columns:
  minmax(380px,1fr) minmax(520px,720px) }
380 + 520 + 24 gap = 924px minimum. On a 390px screen the chart panel and the question both overflow horizontally. Case questions are 6 in a row — a student can lose a whole case block.
BLOCKERGrid rail eats 62% of the screen
.rn-grid { width: 240px; flex-shrink: 0 }
.rn-body { display: flex }
240 of 390px, leaving 150px for the question. The collapsed handle is 32px and still steals width. The code already flags it: “Mobile bottom-sheet variant (covered with the mobile slice)”.
BLOCKERNine controls in one 56px row
Exit · divider · title+meta · counter ·
clock+eye · flag · bookmark · calc · grid
The existing phone rules only strip the text labels. Four icon buttons + a clock pill + a counter + a 320px title still need ~430px. The title/meta line (mode · length · case · CJMM step) has nowhere to go.
SEVEREMATRIX collapses
.rn-matrix { margin-left: 32px }
row template set inline, N columns
390 − 32 indent − 20 padding − border = 336px for a row label plus 3–4 option columns ≈ 70px each. Row labels are full clinical sentences. Unreadable, and the 44px cells become the only thing that still fits.
SEVEREBOWTIE keeps its 3-column shape
.rn-bt-shape { grid-template-columns:
  1fr 1.3fr 1fr; max-width: 600px }
Only the pool below collapses (@720). The shape itself gives each slot ~105px for a clinical phrase, at 12px italic. The pseudo-element connectors also overhang their column.
SEVEREOptions are indented and capped
.rn-options, .rn-opt-count, .rn-matrix
{ margin-left: 32px; max-width: 460px }
The academic indent costs 8% of a phone screen for no reading benefit, and the 460px cap is wider than the viewport anyway. Option rows land at ~38px tall — under the 44px target.
SEVERE100vh + no safe areas
.rn { height: 100vh }
.rn-case/.rn-trend { max-height: calc(100vh …) }
On iOS Safari the footer sits under the URL bar until the student scrolls, so Submit is hidden at the moment it matters. The home indicator overlaps it on gesture devices.
FRICTIONFooter status line
“Untimed Learning · pick an option, Submit
to see the rationale, then Next →”
A 70–100 character sentence between two buttons in a 64px bar (review’s line reads “tap a colour to filter, or step through in order”). On a phone it wraps to three lines or crushes the primary button. It is orientation copy, not per-tap copy.
FRICTIONMeaning lives in hover
@media (max-width:480px) { .rn-flag-btn-label,
.rn-bookmark-btn-label { display:none } }
Flag and bookmark become two similar 14px glyphs with no words and title= tooltips a touch device never shows — exactly the pair the code says must never be confused.
FRICTIONCalculator anchors to the topbar
.calc-panel { right:12px; top:68px;
width: min(264px, 100vw − 24px) }
It fits, but it floats over the question at the top of the screen, away from the thumb, and its keys stay desktop-sized. A dosage calculation needs the pad and the stem visible together.
FRICTIONTrend tables overflow silently
.rn-trend-table { width: 100% }
td.refrange { white-space: nowrap }
Metric + 3–4 timepoints + a nowrap reference range needs ~520px. Inside a phone-width panel the columns crush or the panel scrolls with no affordance saying it can.
FRICTIONThe colour key is now a filter
runner-grid.tsx, 2026-07-31
.rn-grid-legend .row.act[aria-pressed]
Since the rebuild, the rail is three progress buttons (All / Flagged / To do) and every legend row is a real filter button, including a two-swatch “Dropped marks”. Eight 44px controls plus the cells no longer fit one phone-height sheet as a single column — the key goes to two columns, and the old plan of collapsing it into a wrapped one-line legend is dead: you cannot shrink a control to a caption.
ALREADY FINEEvery interaction is a tap
DRAG_CLOZE, DRAG_ORDER and BOWTIE are tap-to-arm / tap-to-place (onClick only — no HTML5 drag, no pointer events). CLOZE uses native <select>. HIGHLIGHT chunks are inline buttons. No interaction model has to be rebuilt — this is a layout and chrome problem.

Part 2 — The system

One rule underneath all of it: the question column is the phone screen. Everything else becomes a sheet you pull up and dismiss. Nothing is deleted, nothing moves to a second page, and the desktop layout is untouched above 900px.

1Two bars, five controls
Top bar carries identity and state — exit, position, clock, flag, overflow. Bottom bar carries movement — back, the primary action, grid. Nine controls become five plus a sheet, and the two thumb-frequent ones (primary, grid) move to the bottom.
2One sheet pattern, five uses
Grid, chart (case/trend), calculator, session menu and results all use the same bottom sheet: grab handle, title row, scrollable body, max 85dvh, scrim dismiss. Learn it once on question 1, reuse it for the rest of the sitting.
3Split → stack, panel → drawer
.rn-split becomes one column. The case/trend panel keeps a persistent 2-line summary card at the top of the question (title + the reason it matters) with View chart; the full chart is a sheet with the tabs intact. The CJMM strip becomes a 6-dot progress row.
4Every answer becomes a full-width row
Drop the 32px indent and the 460px cap under 900px. MCQ / SATA / SELECT_N rows go to 48px minimum. MATRIX becomes one card per row with full-width choice chips. BOWTIE stacks vertically down the wings. The three-channel colour encoding is unchanged.
5Words, not tooltips
Anything whose meaning lived in a title= attribute gets a visible word in the sheet: Flag for review, Bookmark for later study, the mode brief, the grid legend, the disabled-Previous reason. Touch has no hover.
6Real viewport units
100dvh on the shell, env(safe-area-inset-*) on both bars and every sheet, overscroll-behavior:contain on the scroll region. The Submit button is never under the URL bar or the home indicator.

Part 4 — All eleven question types

MCQ · TFDrop the indent and cap, 48px rows. Nothing else.
SATA · SELECT_NAs above. The count line (“2 of 5 picked”) moves to a sticky line just above the bottom bar so it survives a long list.
MATRIX · _MRRow-card stack, choice chips carry the column name as a word. Column headers disappear — they were the only place the choice was named.
BOWTIEVertical: condition → actions → parameters, each wing's pool directly beneath it. Drop the connector pseudo-elements under 900px.
HIGHLIGHTWorks as-is. Raise chunk padding to 7px 6px so a tapped word clears 44px vertically at line-height 1.85 (4px only reaches 39px).
CLOZENative selects already give the iOS wheel picker, and are the one deliberate exception to the 44px floor — forcing the height would break the baseline of the sentence they sit in. min-height 36px, max-width 14ch.
DRAG_CLOZE
DRAG_ORDERAlready tap-to-arm. The inline drop boxes need min-height 44px — at 29px they are the smallest target in the runner. Make the pool sticky at the bottom of the scroll area while a token is armed, so the slot and the pool are on screen together.
Review add-onsScoring strip already has phone rules. The “how others did” dotted-underline hover becomes plain visible text — there is no hover.

Part 5 — How it lands in the code

One breakpoint, one flag
Everything hangs off @media (max-width: 899px) — chosen because that is where .rn-split's 924px floor gives out, so tablets in portrait get the phone layout rather than a broken desktop one. Above it, not one desktop rule changes. Add a single useIsCompact() media-query hook in runner.tsx for the three places CSS cannot reach: rendering the grid as a sheet, the chart as a sheet, and the ⋯ menu instead of four topbar buttons.
New pieces (small)
runner-sheet.tsx — the one bottom-sheet shell (handle, scrim, focus trap, dvh cap, safe-area padding).
runner-session-menu.tsx — the ⋯ contents.
case-summary-card.tsx — the persistent 2-line case/trend header with View chart.
Everything else is CSS in runner.css, plus reusing RunnerGrid and CasePanel unchanged inside the sheet.
Order to build
1. Shell: dvh, safe areas, two bars, mode brief out of the footer. 2. Grid sheet. 3. Options / indent / tap targets — this alone fixes eight of the eleven types. 4. Case + trend stack and chart sheet. 5. Matrix and bowtie reflows. 6. Calculator sheet and the ⋯ menu. Each step is shippable on its own.
