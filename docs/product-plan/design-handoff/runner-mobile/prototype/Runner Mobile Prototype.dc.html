Landscape: no, don't shrink the desktop

Scaling the desktop layout to fit a landscape phone means zoom: 0.62 — the split needs 924 CSS px inside 844. Body copy goes from 15.5px to 9.6px, roughly 1.7 mm of cap height at arm's length, and it overrides the student's own iOS text-size setting. NCLEX stems run 40–80 words.

Height is the real constraint anyway: landscape leaves 390px of it. Today's chrome alone is 120px of that, so a scaled desktop would show about four lines of stem above a chart panel that scrolls independently. The phone layout, tuned for landscape, shows more.

What landscape does instead

A second container query — (max-height: 520px) — keeps the compact layout but spends the width, not the pixels: chrome drops to 44px, the meta line hides, sheets become right-side drawers rather than bottom sheets (a bottom sheet in 390px of height is a joke), and above 760px of width the case/trend split comes back with lower floors (280 / 360) so the chart sits beside the question again.

Flip the toggle above to see it. Same DOM, same classes, third set of rules.

What is real here

Every selector — .rn-opt, .rn-matrix-row, .rn-highlight-chunk, .rn-cloze-select, .rn-dd-slot-row, .rn-bt-slot, .rn-cell, .calc-panel — is the class the components already render, and the icons are the SVGs from runner-topbar.tsx. Delete the one runner-mobile.css link and this is the current runner at any width.

Six additive component changes, all inert above 900px; the list is in that file's header comment.
