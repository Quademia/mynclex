MyNclex · Design proposal 2026-05-19 Payments & Enrolment

Payments & Enrolment — proposed schema and prototype set

Greenfield table model fitted to the 2026-05-19 settled policy, plus four prototype surfaces that exercise the end-to-end flow. Everything below treats the older table sketches inside the plan doc as illustrative, not binding.

01 ·

Recommended slice order

Agreed — start with the off-platform tutor-add flow. It needs none of the heavy infrastructure (no Paystack, no payment Worker, no checkout, no nclex_payments row movement, no bank opt-in card, no installments cron). The whole slice fits in five files: one migration adding nclex_enrolments, a server action that calls auth.admin.inviteUserByEmail, a tiny cohort-workspace page with an "Add student" form, the /welcome page, and a student-dashboard tile read.

  • Slice 1 — Off-platform tutor-add Tutor types name + email → Supabase invite → ENROLLED row with enrolment_source = 'TUTOR_ADDED', cohort_id set. Unblocks tutor-quiz Slice 4 and progress-engine Slice 5 the moment it merges.
  • Slice 2 — Enrolment lifecycle scaffolding The 6-status transitions, pg_cron stub for nightly EXPIRED / PAUSED, the student-tile state matrix, and admin-grant variant. No Paystack yet — synthetic enrolment rows are fine to develop against. This is where the lifecycle state machine gets real.
  • Slice 3 — Programme deltas + discovery + detail page price_currency + price_minor migration on nclex_programmes; payment_collection_mode; access_window_days. Public discovery list + programme detail page (read-only). Still no payment Worker — off-platform cohorts can already accept waitlist sign-ups.
  • Slice 4 — Student-initiated waitlist (off-platform) nclex_cohort_waitlist table + "Join waitlist" form on the cohort row + tutor-side "convert to enrolment" one-click action. Off-platform half of the loop is now end-to-end without ever invoking Paystack.
  • Slice 5 — On-platform checkout (single-strategy) Payment Worker + nclex_products + nclex_payments + bank opt-in card. Ship with upfront-full only. Email-entry dup-check pause is in this slice from day one (cheap; one auth lookup).
  • Slice 6 — Subscriptions + bank standalone nclex_subscriptions + bank-tier purchases. Standalone bank landing page. nclex_subscriptions sits next to nclex_enrolments, not under it.
  • Slice 7 — Multi-strategy + installments nclex_programme_payment_strategies sub-table + nightly cron flip to PAUSED + manual tutor override. This is the most expensive bit — saved for last on purpose.
  • Slice 8 — Self-paced + enquiry routing cohort_id = NULL enrolment branch + show_price_publicly = FALSE contact path + nclex_programme_enquiries queue.
Why not a different first slice? Three alternatives that look tempting on paper — "start with discovery" (no real data to discover yet, has to be back-filled with stubs), "start with /welcome + invite" (still needs nclex_enrolments shape locked to mean anything), "start with bank checkout" (full Paystack lift before any tutor sees value) — all front-load infra without unblocking the two adjacent slices waiting on real enrolment rows. The tutor-add path costs one weekend and immediately turns three slices green.
02 ·

Schema approach

Three principles applied across every table below:

  • Single canonical table per concept. Tutored and self-paced share one nclex_enrolments table (cohort_id is nullable). Payment audit rows for bank and programme share one nclex_payments. Splitting by product type would push policy into joins.
  • Enums as CHECK constraints, not Postgres ENUM types. Easier to evolve, no ALTER TYPE migrations, matches the existing schema's convention (see nclex_attempts.status, nclex_users.role).
  • RLS is the security boundary; TS gates mirror SQL. Every table below has its RLS intent listed in the footer block — those policies are mandatory companions, not "to be added later."

The waitlist table (§10) isn't in your list of greenfield tables but the off-platform flow needs somewhere to put the student-initiated lead before tutor approval. Flagging as a proposed addition rather than assuming.

nclex_programmes — deltas to the live table

migration

Three additive deltas plus one destructive currency migration. The destructive one is non-negotiable per the 2026-05-19 single-currency decision; the others are nullable adds and safe.

nclex_programmes (ALTER)

delta RLS exists

Programme = tutor's reusable template. Cohorts hang off it (tutor-led) or stay NULL (self-paced).

ColumnTypeWhat it does · note
price_currency new TEXT NOT NULL CHECK IN ('GHS','USD'). The tutor picks one. Bank stays dual-currency on nclex_products; only the programme is single-currency.
price_minor new INTEGER NOT NULL CHECK ≥ 0. 0 = free programme (rare but legal — e.g. a tutor's intro programme).
payment_collection_mode new TEXT NOT NULL DEFAULT 'OFF_PLATFORM' CHECK IN ('OFF_PLATFORM','ON_PLATFORM'). Tutor's choice per programme. Self-paced must be 'ON_PLATFORM' — enforced in TS (the doc says so explicitly).
access_window_days new INTEGER NULL = "lifetime of tutor's subscription" per Pattern A. Otherwise N days from nclex_enrolments.enrolled_at. The pg_cron job reads this.
price_minor_ghs drop INTEGER Drop. Backfill: tutor picks GHS or USD pre-migration; non-zero column wins.
price_minor_usd drop INTEGER Drop. Same backfill rule. If both non-zero, default to tutor's account country.
Index(payment_collection_mode) partial WHERE status='PUBLISHED' — feeds discovery filters. RLS intentRead: public can SELECT rows WHERE status='PUBLISHED' AND tutor active. Write: tutor (owner) only. SUPER_ADMIN bypass. MigrationTwo-step: add new cols → backfill from dual GHS/USD → flip NOT NULL → drop old cols. Run inside one tx.

nclex_enrolments

greenfield policy-bound

The most policy-loaded table in the set. Six statuses, three sources, both tutored and self-paced share one shape. Cohort_id nullable.

nclex_enrolments

new

One row per (user, programme, cohort?) triple. Cohort_id NULL for self-paced. UNIQUE constraint blocks double-enrolment within the same cohort but allows across cohorts.

ColumnTypeNote
enrolment_id UUID PRIMARY KEY DEFAULT gen_random_uuid().
user_id UUID NOT NULL FK → nclex_users.id CASCADE.
programme_id UUID NOT NULL FK → nclex_programmes RESTRICT (no orphan rows on programme delete; archive instead).
cohort_id UUID FK → nclex_cohorts RESTRICT. NULL for self-paced. NOT NULL enforced in TS for tutored programmes.
status TEXT NOT NULL CHECK IN ('PENDING_APPROVAL','ENROLLED','PAUSED','REJECTED','CANCELLED','EXPIRED'). Transitions enforced via server actions, not DB triggers (less surprise).
enrolment_source TEXT NOT NULL CHECK IN ('SELF_PAID','TUTOR_ADDED','ADMIN_GRANT').
enrolled_by_user_id UUID FK → nclex_users.id. Tutor or admin who created the row. NULL for SELF_PAID. Audit only.
strategy_id UUID FK → strategies RESTRICT. Set for SELF_PAID on-platform programmes. NULL for off-platform (we don't know how the tutor priced it).
enrolled_at TIMESTAMPTZ NOT NULL DEFAULT NOW()Anchors the access-window clock.
approved_at TIMESTAMPTZ PENDING_APPROVAL → ENROLLED transition timestamp. NULL for paths that skip pending.
approved_by_user_id UUID FK → nclex_users.id. The tutor who clicked Approve. Audit only.
access_expires_at TIMESTAMPTZ Computed at enrolment time from programmes.access_window_days. NULL = "lifetime of tutor sub". Frozen on the row so tutor changing the policy later doesn't shrink existing students' window.
paused_at TIMESTAMPTZ When PAUSED was set. NULL otherwise.
paused_reason TEXT CHECK IN ('INSTALLMENT_OVERDUE','TUTOR_MANUAL'). NULL otherwise.
terminal_at TIMESTAMPTZ When REJECTED / CANCELLED / EXPIRED was set. Indexed for the "wrap up" cron.
tutor_note TEXT Optional reason text on reject/cancel. Shown to admin during refund handling.
created_at / updated_atTIMESTAMPTZ Standard.
ConstraintsUNIQUE (user_id, cohort_id) WHERE cohort_id IS NOT NULL — blocks the "already enrolled in this cohort" case. Self-paced uses UNIQUE (user_id, programme_id) WHERE cohort_id IS NULL. Indexes (cohort_id, status) drives the tutor cohort workspace roster query; (user_id, status) drives the student dashboard; (access_expires_at) WHERE status IN ('ENROLLED','PAUSED') feeds the nightly EXPIRED sweep. RLS intent Read: the enrolled user, the programme's tutor, ADMIN. Write: programme tutor (for status flips on their cohorts) + payment Worker service role (for initial PENDING_APPROVAL creation) + ADMIN. Status transitions are RPC-gated, not raw UPDATEs.

Lifecycle state machine (mirror of the plan's diagram)

PENDING_APPROVAL
Set on on-platform tutored payment. Single entry point. → ENROLLED (approve) or REJECTED (reject).
ENROLLED
Active access. Entered from PENDING_APPROVAL, or directly for off-platform TUTOR_ADDED / self-paced SELF_PAID / ADMIN_GRANT. → PAUSED, CANCELLED, EXPIRED.
PAUSED
Installment overdue or tutor-manual pause. Reversible to ENROLLED by mark-paid / unpause. Can still go CANCELLED / EXPIRED.
REJECTED
Terminal. Tutor rejected a paid-and-pending request. Triggers manual refund.
CANCELLED
Terminal. Tutor/admin terminates active enrolment, or cohort/programme cancelled (cascade).
EXPIRED
Terminal. access_expires_at elapsed. Set by nightly pg_cron SQL function.

Cross-cutting

Nightly pg_cron SQL function

Per 2026-05-19 decision, two transitions run nightly as a single Supabase pg_cron SQL function:

  • ENROLLED / PAUSED → EXPIRED when access_expires_at < NOW(). One UPDATE.
  • ENROLLED → PAUSED when an installment due-date passed and no PROGRAMME_INSTALLMENT row exists with status='ACTIVATED' for that index. One UPDATE + JOIN through nclex_payments.

Function name: nclex_enrolment_nightly_sweep(). Scheduled via cron.schedule('nclex-enrolment-nightly', '0 2 * * *', $$ SELECT nclex_enrolment_nightly_sweep(); $$). Notifications are deferred per the plan — the function writes status flips, not emails.

RLS pattern across the set

  • Three roles consulted via subquery: auth.uid(), EXISTS on nclex_user_roles, and EXISTS on the programme/cohort ownership chain. Standard pattern — same as the existing bank schema's policies.
  • Status-flip writes happen via RPCs, not raw UPDATEs. Policies allow UPDATE only via SECURITY DEFINER functions (nclex_approve_enrolment, nclex_reject_enrolment, nclex_pause_enrolment, nclex_unpause_enrolment, nclex_cancel_enrolment). Keeps the transition rules in one auditable place.
  • Service-role writes (Worker) bypass RLS by design — but the Worker validates the same transitions before writing.

Entitlement read at request time

Programme content access check becomes: SELECT 1 FROM nclex_enrolments WHERE user_id = $1 AND programme_id = $2 AND status = 'ENROLLED' AND (access_expires_at IS NULL OR access_expires_at > NOW()). Bank access: SELECT 1 FROM nclex_subscriptions WHERE user_id = $1 AND pack_type IN ('BANK_DURATION','TRIAL') AND status='ACTIVE' AND end_at > NOW(). Both single-row, indexed.

Genuinely open questions

  • Tutor-sub-lapsed grace period Doc says "length TBD in build, e.g. 90 days." This is a single integer setting; defer to build but flag it now. Storage: a row in nclex_platform_settings (doesn't exist) or a constant in lib/access.
  • Strategy mutation during live enrolment If a tutor edits an installment strategy after students enrolled on it, do existing students keep the old schedule? Proposed: yes — freeze the strategy snapshot on the enrolment row (add strategy_snapshot_json). Otherwise an installment count change retroactively breaks the cron.
  • Self-paced UNIQUE constraint scope Plan doesn't say whether a student can re-enrol in the same self-paced programme after their access expired. Proposed: yes — drop the partial unique constraint and rely on "active enrolment exists" check at checkout. Otherwise a returning student can never come back.
  • Refund row representation Refunds are admin-handled off-platform per plan. Do we still want a REFUNDED status on nclex_payments (proposed yes, for audit) and a "Refund being processed" sub-state on enrolment? Currently mapped to REJECTED — but a refunded ENROLLED student would also need it.
  • Bank opt-in row on programme checkout Single Paystack charge for programme + bank? Or two? Proposed: two separate charges (two nclex_payments rows: PROGRAMME_INITIAL + BANK_OPTIN_AT_PROGRAMME). Cleaner audit, cleaner refund. Cost: two Paystack transactions in one user flow.
  • Per-cohort price overrides Plan keeps pricing on the programme. Some tutors will want "founding cohort = ₵800, later cohorts ₵1,000." Not in v1 per plan. If/when added: a price_minor_override column on nclex_cohorts + strategies referencing cohort instead of programme. Just flagging.
